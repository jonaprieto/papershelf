# biblio-apis

## Summary

All six areas were verified live against real endpoints (curl from this environment, which has genuine network access) or against primary documentation fetched directly and, for the biblatex/CTAN and Crossref-regex claims, downloaded and grepped byte-for-byte; nothing here is guessed. Semantic Scholar's search endpoint and one arXiv title-search attempt hit shared-IP rate limits during testing (documented honestly below with the 429 bodies received) and are backed by official docs plus one successful arXiv id-based call instead of a fresh search response. The design proposes one new pure file, Sources/PaperShelfCore/Metadata.swift, using an injected HTTPFetch closure (mirroring the project's existing @Sendable-closure-injection style already used for MarkdownConverter.arguments and Job.progress), one Decodable struct per source shape, and an explicit field-level merge precedence.

  EVIDENCE: Sources/PaperShelfCore/Hammer.swift:7-8, 24-33, 41-50

- doi.org content negotiation: `curl -H "Accept: application/x-bibtex" https://doi.org/10.1145/3373718.3394769` returns a 302 to `https://api.crossref.org/v1/works/10.1145%2F3373718.3394769/transform`, and the final body is a real BibTeX record `@inproceedings{Fiore_2020, series={LICS '20}, title={Coherence and normalisation-by-evaluation...}, DOI={10.1145/3373718.3394769}, ... year={2020}, month=July, pages={425-439} }`.
  EVIDENCE: live curl -sL -H 'Accept: application/x-bibtex' https://doi.org/10.1145/3373718.3394769, run in this session

  EVIDENCE: live curl -sL -H 'Accept: application/vnd.citationstyles.csl+json' https://doi.org/10.1145/3373718.3394769, inspected with python3 json.load; title/container-title confirmed as str not list

- Crossref's own recommended DOI-matching regular expression, from the blog post 'DOIs and matching regular expressions' by Andrew Gilmartin (2015 August 11), is exactly `/^10.\d{4,9}/[-._;()/:A-Z0-9]+$/i`, stated to match 74.4M of the 74.9M DOIs Crossref had seen; a Wiley-specific supplement `/^10.1002/[^\s]+$/i` catches 300K more, and three further patterns bring uncaught DOIs down to 72K, with the author's own caution that 'each additional pattern...weakens the overall precision of the catch.'
  EVIDENCE: downloaded the raw HTML of https://www.crossref.org/blog/dois-and-matching-regular-expressions/ and grepped it directly; exact substring '10.\d{4,9}/[-._;()/:A-Z0-9]+$/i' extracted verbatim, with surrounding plain-text context confirming author, date, and the 74.4M/74.9M and 300K/72K figures

## Risks

- The doi.org -> csl+json shape and the api.crossref.org/works/{doi} shape were verified only for one Crossref DOI and one DataCite DOI; mEDRA-registered DOIs (the third agency citation.doi.org names) were never tested live, so CSLWork's leniency for a mEDRA response is unverified.

- OpenAlex's authentication policy is ambiguous right now between two of its own sources (mandatory-key announcement vs. still-open docs and live 200s); building against 'no key needed' could break without warning if OpenAlex finishes rolling out mandatory keys, so the design should treat an eventual api_key parameter as a near-certain follow-up, not a remote possibility.

- Semantic Scholar's search endpoint could not be exercised live in this session (persistent 429 from a shared sandbox IP); its documented shape (verified via its own swagger.json and GitHub release notes) should still be treated as slightly less battle-tested here than the sources that returned live data.

- The DOI regex's own trailing-punctuation 'bycatch' was reproduced, not fixed; any caller trimming a trailing '.' risks truncating a DOI whose suffix legitimately ends in a digit followed by a sentence-final period one character later in the source text -- Crossref's own blog treats this as an open, unsolved edge case, and this design does not invent a fix beyond what was verified.

- The year-precedence rule in the merge function (venue year over arXiv posting year, when both exist) is a design judgment, not something any of the five APIs or biblatex/BibTeX conventions mandates; some citation styles prefer the original preprint year. It should be exposed as a configurable choice rather than hardcoded if the app's users care about this distinction.

- BibType currently has no inproceedings case and Crossref's type vocabulary has 30 values (only a handful of which were inspected in depth); a full bibType(forCrossrefType:) mapping needs a deliberate pass over the full /types list rather than the partial mapping sketched here.
